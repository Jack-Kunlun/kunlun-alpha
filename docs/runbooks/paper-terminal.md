# 模拟组合终端运行手册

## 当前能力

### 1.0.12 本地账户与只读账本

- v1 启动读取已有 `kunlun-quant-state` 独立卷。页面 `/paper` 展示模拟账户的初始资金、现金、
  持仓成本、持仓、账本时间和持久化状态；金额保留原始十进制文本。
- 没有账户时点击“创建账户”打开短弹窗。提交失败保留输入，相同输入重试沿用同一
  `clientRequestId`；修改输入才生成新键。成功关闭弹窗并显示服务端账本。
- 页面仅展示账本资金与持仓成本，不接实时行情，也不展示旧手工标记的市值或收益。
  数据时间按账本实际时间展示；
  无持仓明确为空，不补造股票、价格或估值。切换全局历史点时不会回放该当前模拟账本。
- v1 固定 `PAPER_TERMINAL_ACCOUNT_ONLY=true`，Nest 在转发前拒绝 `POST /paper/simulations`。
  `quant-engine` 仅在 Compose 内部提供服务，不发布主机端口。旧演练入口继续关闭；当前受控买入另见 1.0.15。
- Nest 对引擎响应按模拟语义、金额、数量、时间、摘要和账本关系检查；异常返回不可用，
  不把坏金额替换为零或纠正后继续展示。账号与 CSRF 沿用单管理员现有认证。

### 1.0.13 只读仓位试算

已有正常账户时点击“试算仓位”打开抽屉，输入规范证券代码、人工假设价格、信号强度、
假设可信度和整手单位。价格不读取行情，参数不冒充模型输出。成功关闭抽屉，页面显示
目标持仓、增减数量、假设调整金额（未含费用）或拒绝原因；失败保留输入并允许重试。
刷新账本或重新打开抽屉清除上次试算结果，试算结果不保存到服务端日志。

- 固定策略口径 `paper-preview-allocation / 1.0.0`：目标权重为强度 × 可信度，单标的上限
  30%，组合总权重上限 95%，保留 5% 账面现金；假设可信度低于 0.5 时拒绝。
- 价格、信号和整手单位均为人工假设，不自动识别交易所最小委托、涨跌停、停复牌或可成交性；
  该结果不是交易建议、风控许可或可执行报价。仍不开放成交接口。
- 复用当前账本的既有估值作为分配基准，不引入新行情估值；异常账本停止试算。
  所有计算在 Python 通过 Decimal 进行，数量超过 JavaScript 安全整数范围时拒绝。
- `POST /api/v1/paper/previews` 使用现有管理员认证和 CSRF，内部对应 `/v1/paper/previews`。
  它只读取账户，不登记请求、不写命令、订单、风险结果、现金、持仓、估值或审计计数。
- 输入复用 `PaperTerminalSimulationCommand`（`paper-terminal-simulation-v1`），只是情景输入形状；
  端点决定只读语义，不能把此请求转发到 `/simulations`。`clientRequestId` 仅参与预览输入身份，
  不占用已提交命令的幂等登记，相同 ID 的不同预览可重新计算。既有创建／成交命令语义不变。
- 输出复用 `PaperAllocationDecision`（`paper-allocation-decision-v1`），保持
  `INTENT_ONLY_NO_BROKER_PATH`、`PAPER_ONLY` 和 `brokerExecutable=false`；字段兼容，无 Schema 变更。

请求示例（仅假设输入，不含账户或行情来源）：

```json
{
  "schemaVersion": "paper-terminal-simulation-v1",
  "clientRequestId": "manual-preview-example",
  "instrumentId": "600519.SH",
  "price": "100",
  "score": "0.3",
  "confidence": "1",
  "lotSize": 100
}
```

在账面基准为 100000 CNY、未持仓的隔离测试中，上述假设产生 300 股目标，
假设调整金额 30000 CNY（未含费用），原账户现金与持仓不变。

### 1.0.14 只读模拟风险检查

在有调整数量的仓位试算结果下点击“检查模拟风险”，展示账户、引擎、执行入口、实际账簿
核对、单笔金额、集中度、当日累计假设金额、活动订单、账面现金和仅模拟边界共十项结论。
该版本的模拟执行入口固定为“未开放／阻断”，整体结果不构成交易许可。金额仍是人工价格下的假设，
现金检查未计费用；没有订单、成交或账户变化。

- 新入口 `POST /api/v1/paper/risk-previews`（HTTP 200）沿用管理员认证及 CSRF；内部路径同名。
  请求是 `/previews` 返回的完整、未修改的 `paper-allocation-decision-v1` JSON，不能只发证券或数量。
  示例调用顺序：`allocation = POST /previews(上述情景)`，然后 `POST /risk-previews(allocation)`。
  无调整意图、快照被修改或计算不一致返回 400／422；账户基准已变化返回 409，须重新试算。
- 复用 `paper-risk-decision-v1`：`intentId`、`accountId`、`accountStateDigest` 绑定原试算，
  `decisionTime` 为本次检查时间，`allowed=false`、`PAPER_ONLY`、
  `SERVER_SIDE_RISK_NO_BROKER_PATH`。字段及 Schema 兼容；控制面校验十项完整性、金额、
  状态、策略指纹与结论摘要，不把异常响应当作通过。
- 风险口径 `paper-terminal-risk / 1.0.0`：单笔假设金额不超过 100000000 CNY，目标权重不超过
  0.35，当日累计假设金额不超过 1000000000 CNY，活动模拟订单不超过 20，试算后现金不低于 0。
  这些是既有隔离模拟规则，不能作为真实交易规则或费用充足性证明。
- 引擎在同一锁内读取账户和执行投影，重算试算并核对完整快照，重新比较实际账簿。
  不沿用旧的对账“通过”状态；对账差异或不可用按阻断处理。执行入口始终关闭。
- 检查不登记幂等命令，也不写入风险结果、日志、审计、订单、现金、持仓或估值。
  失败保留本次试算并可重试；重新打开试算抽屉或刷新账本清除试算和风险结果。
  检查结果只留在当前页面，不保存为服务端历史记录。

### 1.0.15 受控模拟买入

试算得到买入数量后，先点击“检查模拟风险”。启用状态、账簿、现金与手续费等条件满足时，
再点击“模拟买入”，在短弹窗核对证券、数量、人工价格及费用口径后确认。服务端仍会重新
计算及核对；成功关闭弹窗，更新模拟现金、持仓成本和订单记录。失败保留试算和弹窗，
提示核对或重试；重复提交同一份快照不会重复成交。

- 仅按人工参考价做一次全额模拟买入；价格最多支持 8 位有效小数，不读取真实行情或成交量，
  不模拟停复牌、涨跌停、真实流动性、部分成交、卖出或跨日可卖释放。新增持仓可用数量为 0。
- 模拟手续费口径 `controlled-paper-buy / 1.0.0`：金额 × 0.0003，最低 1 CNY，按分使用
  ROUND_HALF_EVEN 舍入，计入持仓成本。它是隔离模拟口径，不能表示交易所或券商真实费率。
- 新 `POST /api/v1/paper/buy-simulations`（HTTP 200）沿用管理员认证和 CSRF。
  请求复用 `/previews` 返回的完整 `paper-allocation-decision-v1` JSON；例如
  `allocation = POST /previews(上文情景)` → `POST /risk-previews(allocation)` →
  `POST /buy-simulations(allocation)`。后者响应复用 `paper-terminal-workspace-v1`；无 Schema 变更。
- 同一快照的幂等键为 `buy:` 加 `decisionId`；重复请求返回当前账本，其中原模拟订单仍只出现一次。
  修改过的快照失败，账户基准变化返回 409，须重新试算；不把过期预览自动替换成另一笔数量。
- 新交易先在内存计算完整计划：核对账户与快照、实际双账簿、未结束订单、限额、含费用现金，
  通过创建／风险检查／提交／全额成交状态，再验证账户与执行账簿一致。全部通过后才写日志并
  应用已验证事件。任一前置失败不会追加日志、订单、现金、持仓或审计。
- 原 `/simulations` 仍由 `PAPER_TERMINAL_ACCOUNT_ONLY=true` 拒绝，不复用其旧演练写入流程。
  新买入必须同时启用控制面 `PAPER_TERMINAL_CONTROLLED_BUY_ENABLED=true` 与引擎
  `KUNLUN_PAPER_CONTROLLED_BUY_ENABLED=true`，并具有持久日志；普通开发进程默认关闭。
  本地 v1 统一由 `V1_PAPER_BUY_ENABLED` 控制，默认 true；quant-engine 仍不发布主机端口。
- 启用时，只读风险预览会以实际买入可用条件报告执行入口，`allowed` 等于十项检查全部通过；
  卖出、费用不足或不适用的精度会保持阻断。预览仍不写入状态；提交会再次核对，不复用旧风险许可。
- 试算使用统一 128 位上下文生成并校验账户摘要，避免平均成本为循环小数时出现摘要差异；
  旧 `CREATE_ACCOUNT`／`SIMULATE` 日志仍走原重放路径。新交易同时验证账面金额在历史重放上下文
  下不改变，无法一致时在写日志前拒绝。

**重试、恢复与回退**：`BUY_ALLOCATION_V1` 使用既有哈希日志封装，支持混合读取旧日志；
新命令类型须使用 1.0.15 及以后引擎。写日志或提交结果不确定时，实例停止后续账本使用及
写入，workspace／health 返回不可用；保留卷，重启引擎重放后核对原订单，再重试同一快照。
截断或校验不通过的日志仍拒绝加载，不能删掉尾部来假装恢复。

需要暂停新买入时，在本地 Compose 的环境文件将 `V1_PAPER_BUY_ENABLED=false`，再用同一
配置更新 server／quant-engine；已成交数据仍可读取和重放。页面可回退，但已有新命令后必须
保留新引擎和卷，不能让 1.0.14 引擎读取或改写该日志。本片不代表完整节点或 Phase 6 退出。

### 1.0.16 只读账簿核对报告

已有模拟账户时，在 `/paper` 点击“核对账簿”，重新计算当前时刻的执行流水应有账簿，
与账户账面现金、各证券持仓数量及成本比较。报告显示核对时间、一致／差异状态、差异项数、
去重成交数；差异表保留原始十进制文本，差额等于“账面值 − 应有值”，金额单位为 CNY。

- 新入口 `GET /api/v1/paper/reconciliation`，内部为 `GET /v1/paper/reconciliation`，
  HTTP 200 响应复用 `paper-reconciliation-result-v1`。无需请求体，沿用现有管理员认证。
  无账户返回 400（内部 422），引擎不可达、写入结果不确定或响应不可信返回 503。
- 响应示意：`status="MATCHED"` 时 `diffs=[]`；`status="DRIFTED"` 时展示
  `diffs=[{kind:"CASH", instrumentId:null, expected:"100000.01", observed:"100000", difference:"-0.01"}]`。
  `asOf` 是本次核对时刻，`accountId` 绑定账户，`executionCapability="PAPER_ONLY"`，
  `dataMeaning="SIMULATION_BOOK_RECONCILIATION"`；摘要与 `reconciliationId` 保留来源身份。
  示例仅说明字段，不代表原账户存在差异。
- 引擎同一锁内读两本账，使用零容差；每次重新计算，不把旧 `_latest_reconciliation` 当作当前报告。
  核对使用独立 Decimal 128 位／ROUND_HALF_EVEN 上下文，不受调用者精度设置影响。
  不登记命令、更新缓存结果或写入日志、审计、订单、现金、持仓、估值。读取不需要开启新买入。
  控制面按字段、时间、金额、差额算术、状态及摘要关系校验后才返回。
- 报告只反映核对时刻，不提供自动修复或交易许可。异常时先核查模拟订单与流水，
  不在原账本注入差异或删除日志；恢复仍按下节既有流程执行。
- 失败保留上次成功返回的报告及原时间，并明确不能确认当前状态。账户／账本刷新或成交后清空，
  旧异步响应不覆盖新页面；结果只留在页面，不新增服务端报告历史。
- 不改变已有受控买入、日志兼容性或 Phase 6 退出边界；不接实时价格、卖出或真实券商。

### 1.0.17 核对报告下载

在 `/paper` 完成本次核对后，点击“下载核对报告”，浏览器生成 UTF-8 JSON 文件。
内容完整复用该次 `paper-reconciliation-result-v1`，保留原始 `asOf`、账户绑定、报告身份、
两本账簿摘要、去重成交数、状态和差异；差异中的金额保持十进制字符串，数量也按契约表示。
文件时间取原报告的核对时间，不用下载时间冒充一次新核对；文件名使用 UTC 时间与报告摘要前缀。

- 一致报告的 `diffs=[]` 仍可下载；差异报告保留全部现金／数量／成本差异，不丢弃负号或尾数。
  JSON 不将长金额转换为 JavaScript Number，也不含 CSV 公式或表格软件的自动数值转换。
- 无有效报告、账户／基准不匹配、重新核对中、本次核对失败、账本操作中均停用下载并解释原因。
  失败后仍显示旧报告，但需重新核对成功才能下载，避免旧结果被误认成当前状态。
- 下载失败保留当前报告并允许重试；新报告或页面刷新不会沿用旧下载提示。
  点击只生成当前快照文件，不发出新的 API 请求，不写报告历史、命令日志或账本。
- 文件只包含核对结果，不包含完整现金／持仓明细、完整账户流水或恢复命令；不是备份、导入格式、
  自动修复或真实券商对账。已有持久化与恢复步骤不变。
- 无新 API、Schema、依赖或迁移；报告读取的既有管理员鉴权和模拟边界继续适用。

### 1.0.18 模拟账户成本与费用总览

`/paper` 在基础账户摘要下展示同一 `paper-terminal-workspace-v1` 的成本与费用：

- **持仓成本合计**：当前所有持仓的 `costAmount` 精确求和。它包含相应买入费用，
  不代表行情市值、累计买入金额或收益；卖出后的剩余成本仍以服务端账本为准。
- **累计模拟手续费**：全部订单的 `totalFees` 累计，覆盖买入／卖出与部分成交后取消的已发生费用。
  订单按唯一 `orderId` 计入一次，未成交的订单只能为零费用；不按手续费公式重新估算。
  此项单独披露，不能再次叠加到持仓成本上。
- **有成交订单数**：`filledQuantity > 0` 的订单数，与成交回报条数区分；费用为零的真实模拟成交仍计数。

例如现有隔离买入样例的 300 股、人工价格 100、手续费 9 CNY，显示持仓成本 30009 CNY、
累计手续费 9 CNY、有成交订单 1 笔，不把成本再加一次手续费。有效空账户明确显示三个零值。

金额使用十进制字符串与 BigInt 对齐小数位求和，不转换为 JavaScript 浮点数；页面只显示汇总，
不改变原始行数据。重复订单、非法金额、无成交却有费用、晚于工作区快照的订单事实均拒绝汇总，
并提示刷新核对。异常账本继续显示异常提示，不能把汇总出现当作账本恢复。
汇总标明工作区生成时间，沿用页面已有加载／无账户／无权限／不可用状态。

只增加只读展示；无新 API、Schema、依赖、费用策略、估值或入账路径。
量化引擎、原始持久日志、下载报告格式和恢复步骤均不变。

### 1.0.19 模拟研究到标的日线

试算结果标题、持仓表及模拟订单记录的证券代码均可点击或用键盘打开既有标的日线页。
确认模拟买入弹窗仍只展示确认信息，不增加导航或交易操作。

- 仅规范 `600519.SH`／`000001.SZ`／`920000.BJ` 等内部代码生成站内 `/instruments/:instrumentId`
  路由；非法代码不生成可操作链接。沿用页面既有管理员认证及目标路由权限，不绕过守卫。
- 目标为当前已入库日线研究视图，URL 不携带 `asOf` 或其他证券筛选，避免把另一页面的历史上下文
  误当作本次查询；浏览器返回可回到原 URL。当前模拟账本本来就独立于全局历史点时。
- 日线继续显示真实来源、行情日期、数据状态及既有窗口，不保证每个规范代码都有行情；没有覆盖时
  使用目标页现有无数据／不可用状态，不自动采集、不用人工假设价补造日线。
- 查询行情不会更新模拟假设价格、持仓成本、估值、手续费、风险许可或账本；不新增下单行为。
  试算结果仍是临时页面状态，离开后返回可重新试算，不把它当成持久账本或成交记录。
- 导航规则与提醒入口复用同一私有前端 helper；提醒的已有当前研究语义保持不变。
  无新 API、Schema、依赖、数据来源或会计路径；创建／买入、日志及恢复步骤均不变。

## 既有引擎能力与开发栈

- `quant-engine` 维护一个模拟账户、账户事件链和模拟执行事件链；本地 Compose 通过独立持久卷保存命令日志。
- 既有开发引擎可运行 Signal 到 OrderIntent、服务端风控、模拟全额成交和双账簿对账闭环；
  完整旧演练入口未在当前产品中开放；当前只开放下述受控买入切片。
- 金额使用十进制字符串；订单固定为 `PAPER_ONLY`，不存在真实账户、券商连接或真实下单入口。
- `clientRequestId` 对创建账户与模拟命令提供幂等保护；相同键的不同载荷会 fail closed。

## 持久化与恢复

- 设置 `KUNLUN_QUANT_STATE_DIR` 后，创建账户和模拟命令在执行前写入 `paper-workspace.jsonl`。日志按序号和 SHA-256 前序摘要连接，写入后执行 `fsync`；重启会从头验证并重放，再重新生成账户、订单、风控和对账状态。
- 日志缺字段、顺序断裂、摘要不符、载荷不合法或重复命令时，quant-engine 拒绝启动，不会用空工作区掩盖损坏。
- 未设置 `KUNLUN_QUANT_STATE_DIR` 的测试进程仍使用 `VOLATILE_IN_MEMORY`；正式本地 Compose 使用 `DURABLE_COMMAND_JOURNAL`。
- 本地日志只支持单个 quant-engine 实例，不是多副本共用的分布式日志。备份或恢复时必须把服务停在单实例边界，并保留整个 `kunlun-quant-state` 卷。

## 已知限制

- 既有开发引擎仅支持手工多头信号的全额模拟成交，不提供真实行情执行、部分成交输入或跨日可卖数量释放。
  当前仅开放受控模拟买入，不提供模拟卖出或跨日可卖数量释放。
- 24 小时 P6 墙钟门禁使用独立 PostgreSQL 证据库；本地命令日志恢复不能替代该门禁，也不能据此宣称 Phase 6 已退出。该资格不构成实盘许可；真实交易前仍须取得独立的连续 72 小时合格耐久证据并通过全部 Phase 7 门禁。

## 启动与健康检查

本地产品使用现有 `pnpm v1:up`。行情自动采集仍单独使用 `pnpm v1:auto:start`。
停止本地产品使用 `pnpm v1:stop`，同时停止模拟引擎并保留独立持久卷。
只读健康检查可经控制面读取 `/api/v1/paper/workspace`；内部引擎健康由 Compose 检查，
v1 不使用主机 `8081`。已有命令日志必须保留，不能因不可用而删除或重建账户。

以下为保留的开发栈入口，不代表 1.0.12 的产品能力或范围：

```text
docker compose -f infra/docker/docker-compose.yml -f infra/docker/docker-compose.apps.yml --env-file infra/docker/.env up -d --build
curl http://localhost:8081/health
curl http://localhost:3002/api/v1/paper/workspace
```

Web 页面：`http://localhost:5173/paper`。

Ranking 正式页面只读取 quant-engine 已发布的版本化快照。若尚未发布，页面显示空状态；测试验收 JSON 不会作为运行时回退数据。

## 故障处理

1. `quant-engine` 不健康时检查容器日志和 `KUNLUN_PORT`。
2. Nest 返回 `UNAVAILABLE` 时检查 `PAPER_ENGINE_URL` 与容器网络。
3. quant-engine 因日志损坏拒绝启动时，先复制并保全 `kunlun-quant-state` 卷；不要删除日志或改写摘要来强行启动。
4. 对账结果为 `DRIFTED` 时停止新增模拟命令，保留响应中的摘要和差异，再调查命令日志与账户/执行摘要。
5. 不要通过重试更换 `clientRequestId` 绕过冲突；先确认原命令是否已提交。
