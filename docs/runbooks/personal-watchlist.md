# 服务端个人自选与日线

个人自选属于当前登录账号，保存在 PostgreSQL；浏览器旧清单仅用于一次性迁移和保留备份。迁移或导入返回完整列表并确认代码后才显示成功。服务端已存在的同代码名称保留不变。个人截图、导入文本与运行数据不得提交 Git。

## 接口

既有认证、Cookie 和 CSRF 规则适用，客户端不能指定所有者。

- `GET /api/v1/personal-watchlist`：读取本账号列表及各标的采集状态。
- `POST /api/v1/personal-watchlist/import`：追加合并，最多 2000 项；`clientRequestId` 为 UUID。相同请求安全重试，复用请求编号但改变内容返回 409；校验或事务失败不保存部分列表。

```json
{
  "schemaVersion": "personal-watchlist-import-v1",
  "clientRequestId": "00000000-0000-4000-8000-000000000001",
  "items": [{ "code": "600000.SH", "name": "示例股票" }]
}
```

新接口为兼容性增量，Schema 使用 `personal-watchlist-import-v1` / `personal-watchlist-response-v1`。价格继续使用既有点时日线接口；状态任务时间不冒充行情日期。页面按 20 项分页，仅查询当前页的真实日线。

## 1.0.8 市场与搜索筛选

“我的自选”支持全部市场、上海（`.SH`）、深圳（`.SZ`）、北京（`.BJ`）及未接入观察项，
可与代码或名称搜索组合。搜索忽略大小写和首尾空白；先筛选完整的服务端清单，再按原顺序
每页显示 20 项。“显示 X / Y 项自选”表示匹配数量与本账号已读取的自选总量，不是市场覆盖率。

改变市场、搜索或点击“重置筛选”均回到第一页；重置同时清空搜索并恢复全部市场。导入成功
也会恢复全部市场和第一页，便于查找新增项。无匹配时保留筛选控件并提示调整条件，与尚未
保存自选的空清单区分。筛选仅影响当前页面展示，不更改服务端清单或采集任务。

未接入观察项依据既有代码格式（`HK:`、`NEEQ:`、`SGE:`）归类；采集失败、等待中或源暂无
行情的沪深北标的仍归入对应市场，不按任务状态改成未接入。分类不代表行情健康、完整率
或主数据生命周期已验证。不会为筛选而批量读取全部自选行情，仍只查询当前页。

## 1.0.21 本页日线对比

在“我的自选”筛选或翻页后，点击“对比本页日线”打开已有 Dialog 抽屉。只捕获打开时本页
最多 20 项中的规范沪深北代码，港股／新三板／上金所观察项不参与；没有合格标的时入口禁用。
本次标的名称与顺序固定，服务端列表后台刷新不会改换正在查看的选集。

当前模式在打开时固定查询点时；有历史点时则沿用该点时。通过既有 bars 接口读取每项最多
两根可见日线，最多 4 个并发请求，不增加外部采集或写入。关闭后不再启动排队读取，已在途
读取的结果不会覆盖新查询。“重新查询”保留本次选集和点时；需要最新快照时关闭后重新打开。

排序只作用于本次本页样本，不代表全部自选或全市场排行。来源／数据版本不一致、日期／
基准日期不一致、停牌、前收无效时保留既有说明，不计算相应涨跌幅。点时校验保留纳秒
精度，事件／可见／处理时间晚于截止点的记录拒绝展示为有效行情。日线不是实时或可成交价。
点击证券名称按本次固定点时打开详情，不继承其他证券筛选；返回后可再次查询。

## 启动与更新

先执行 server migration 012，再使用与应用相同版本的 `kunlun-data-worker:local` 镜像：

```text
docker compose -f infra/docker/docker-compose.yml -f infra/docker/docker-compose.apps.yml -f infra/docker/docker-compose.v1.yml --env-file infra/docker/.env --profile real-market-data up -d watchlist-market-data-sync
```

任务读取服务端已保存代码，每 60 秒发现新增项；上海时间每日 09:00 后更新既有项。沿用 AKShare 1.18.94、不可变 raw、Decimal 标准化、ClickHouse 日线与持久检查点。个人自选的采集状态和检查点独立于原有样本概览。默认回溯 730 天；空响应明确标记 `EMPTY`。同代码通过数据库锁隔离并发；失败逐项隔离，每天最多尝试三次且间隔至少一小时。重启复用检查点，失败保留最近成功时间和已入库历史。

进程使用既有 PostgreSQL/ClickHouse 环境配置和 raw volume，密钥只由环境注入，不输出个人代码、名称或账号。数据库不可用时记录脱敏错误并等待下次检查；单项来源、验证或存储失败按对应错误码显示。健康排查先看容器是否运行、最近聚合进度、数据库状态与实际 bars 查询，不将容器存活等同于行情成功。

## 支持边界

沪深北股票、指数、ETF 和 LOF 使用未复权日线，供研究参考。沪深使用 Tencent，北交所日线明确使用东方财富 `stock_zh_a_hist` / `bj-v1`，成交量从手转为股；来源直接显示在页面，不静默切源。LOF 使用独立 `lof-v1` 标准化版本，暂不开放分钟行情。Tencent `v4` 仅以 Decimal 修正已核实 SDK 浮点乘法产生的不超过 `0.000001` 股的整数尾差，真实小数股仍拒绝，历史 `v1`–`v3` 保持严格原样回放。新解析使用独立检查点命名空间，旧 raw、拒绝证据和检查点保留。

每标的整段 SDK、raw 和入库操作由独立子进程限制为 90 秒，超时终止并释放锁。修复来源或解析后，可用单次模式 `personal-watchlist-sync --retry-failed-once` 立即重试失败项；要求 `WATCHLIST_SYNC_RUN_MODE=once`，仍保留每日三次上限，成功项不重采，不修改真实尝试时间。

港股、新三板和上金所引用保存在服务端并明确标为未接入，不转换成 A 股标识，不产生订单。行情缺失、停牌、陈旧日期和源错误须如实展示；已有行情不代表主数据生命周期或所有研究字段均已覆盖。

停止只需停止 `watchlist-market-data-sync`；不删除自选和日线。迁移为新增表，备份当前数据库后执行；重复执行跳过已应用版本。回退应用时保留这些表及 raw 数据，避免丢失已导入自选，不通过删表回退。
