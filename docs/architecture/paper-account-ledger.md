# 模拟账户不可变账本

## 边界

`paper-core` 负责模拟账户的生命周期、现金、持仓成本与点时 NAV。它不包含 broker SDK、账户凭据、真实订单接口或可切换到实盘的执行适配器，执行能力恒为 `PAPER_ONLY`。

回测账户和模拟账户使用相似的会计不变量，但生命周期不同，因此不复用可部署服务状态，也不把模拟账户写入 `backtest-core`。

## 事件带

每个账户只有一条追加式事件带：

- 事件序号必须连续。
- `previous_event_digest` 必须指向前一事件。
- `event_id` 的完全重复是幂等操作；同 ID 不同内容直接拒绝。
- 写入使用 `expected_tape_digest` 做乐观并发控制。
- 事件按 `available_time` 对外可见，点时查询不会读取未来可用事件。

账户状态只能由事件重放得到。任意历史时点使用 `replay_account(..., as_of=...)` 重建，不保存可被覆盖的权威余额快照。

## 资金与持仓不变量

- 所有金额使用 `Decimal`，禁止二进制浮点进入领域边界。
- 模拟持仓转移要求 `cash_delta + position_cost_delta = 0`。
- 现金、持仓数量、可用数量和持仓成本不得为负。
- 可用数量不得大于总持仓数量。
- 持仓归零时，可用数量和成本必须同时归零。
- 每次估值必须完整覆盖当前全部持仓，且估值证据的 `available_time` 不晚于估值事件。
- NAV 恒等于现金加持仓市值。

## 生命周期

账户创建后为 `ACTIVE`，可进入 `SUSPENDED`，再恢复为 `ACTIVE` 或关闭。存在持仓时不能关闭；`CLOSED` 后禁止追加任何业务事件。

## 后续适配

撮合、成交和对账节点只能通过新增明确事件扩展该账本，不能直接修改 `PaperAccountState`。持久化适配器必须实现同样的事件唯一性和 `expected_tape_digest` 并发语义。
