# 昆仑智策 1.x.x 小版本开发任务

更新日期：2026-10-16。后续任务均为 `planned`，首发目标是 `1.0.0`；当前本地验收通过不等于已创建该版本。以下计划替代此前按大模块直接推进 1.1、1.2 直至 2.0 的安排。

每个版本交付一项能使用的模块增量，目标 2–5 个自然日，**从开始投入到可交付最多 7 个自然日**，包含必要调研、实现、检查和发布收尾。按可用结果发布，不把完整模块、整个 Phase 或纯内部进度作为一个版本。

新周期规则约束此后开工的迭代。`1.0.0` 已有历史开发投入，下面只调整剩余收尾窗口，不将此前耗时重新记成一周内完成。

## 版本规则

- 使用完整三段版本号：`1.0.0 → 1.0.1 → 1.0.2 → 1.0.3`。本项目补丁号承载向后兼容的小功能、使用体验改进和修复，不为每个小功能增加次版本号。
- `1.1.0` 留给已经形成明确产品里程碑的实质增量，该次交付同样不得超过一周；不按周自动升次版本，也不为了版本号单独发布空更新。
- 不预定 `2.0.0`。只有实质不兼容或产品边界变化时再决定主版本；QMT 接入本身不自动触发主版本升级。
- 产品版本与 API/Schema 版本分开管理。使用补丁号不允许偷偷破坏公共契约、迁移兼容性或安全边界。
- 版本号在范围冻结时确认；每版保留实际版本、一个可观察结果、简短变更说明和检查结果。规划号不写成已经发布的 tag、包版本或部署版本。

## 近期版本任务

下表工期是包含验证和收尾的投入预算；每版只做所列的一条可用链路。先锁定 `1.0.0`、`1.0.1`，后面的顺序按真实前置就绪情况滚动调整。

| 目标版本 | 模块切片与开发任务                                                                     | 用户能用到的内容及最小验收                                                      | 前置与预算                                                                               |
| -------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 1.0.0    | 首发收口：固定实际源码/构建、确认阻断、形成正式版本记录；复用现有验收                  | 登录后查看 8 个标的真实日线、样本概览，创建/编辑/启停价格和涨跌幅提醒           | 本地功能已验收；剩余版本冻结与发布操作。10 月 19 日候选、20 日正式为目标，不再等到 26 日 |
| 1.0.1    | 更新状态：采集结果记录 → 查询接口 → 现有日线页面；区分最近尝试、最近成功和数据日期     | 能判断行情什么时候更新、是否失败；失败不覆盖上次成功数据，无记录时明确显示未知  | 复用当前单次采集和查询链路；2–3 日                                                       |

真实使用中出现的阻断修复可以优先成为下一个补丁版本，后续规划号顺延。修复版要说明用户可观察的改善，不预造缺陷、不为凑频率发布空版本。

## 下一版执行任务 1.0.1

**结果**：现有日线页面可以准确回答“上次更新何时成功、最近一次是否失败、行情截至哪一天”。

| 顺序 | 开发任务                                                                                            | 涉及范围                                                       | 直接验收                                                           |
| ---- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------ |
| 1    | 沿用采集链路记录真实尝试/成功时间、结果、样本数和可公开的错误原因；先核对已有记录能力，缺什么补什么 | `services/data-worker` 采集运行与状态存储边界；P1-N11 对应切片 | 成功后日期和时间来自实际任务；失败保留上次成功状态；日志不泄露凭据 |
| 2    | 提供最小状态查询，显式区分未知、运行中、成功与失败；沿用现有认证和契约                              | `apps/server` 对应查询、共享契约                               | 未授权不可读；无记录显示未知；任务时间不冒充行情日期               |
| 3    | 在现有市场/标的日线区域展示状态和失败提示                                                           | `apps/web` 现有日线页面；P6-N02/N06 对应切片                   | 浏览器能看到真实状态和数据截止时间；外部失败时旧行情仍明确标注日期 |

范围只包括状态链路；自动采集留到 `1.0.2`，新增标的留到 `1.0.3`，不新建运维后台。开发节点按手册前置逐个验收，不把这一版本作为一个跨节点大任务。

预算：第 1 日完成状态边界和记录，第 2 日接接口/页面，第 3 日完成相关检查与版本收尾。状态记录、无记录、失败保留旧成功值做定向测试；执行受影响静态检查，必要时一次受影响构建；最后一次浏览器状态检查。涉及持久化的实际变更保留一次独立审查，不重复现有备份恢复演练。

## 后续模块继续拆成可用切片

以下任务池暂不占具体版本号；只有来源、权限和节点前置就绪、单片可在 2–5 日交付时，才进入后续 `1.0.x` 或适当的 `1.x.x`。一个模块允许通过多个补丁版本逐步开放。

| 模块           | 可分别交付的切片顺序                                                         | 必要前置                                                                                     |
| -------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 市场分析       | 单一真实来源的日终涨跌停清单 → 情绪历史曲线 → 单板块强度 → 板块轮动记录      | P1 数据前置和 P2 对应事实/算法；缺实时事实时不展示炸板、封板过程等未支持指标                 |
| 事件热点       | 一个来源的真实事件列表和原文 → 单类事件关联个股 → 已入库事件的热点聚合       | P3 持久采集和证据；LLM、反馈分别作为后续切片，模型和可信身份未具备时保持关闭                 |
| 席位与 KOL     | 单源龙虎榜事实明细 → 席位历史 → 一个合格来源的 Claim 时间线 → Claim 表现统计 | P4 真实采集、持久投影、来源权限和可信审核；Claim 不能表示券商确认成交                        |
| 研究回测       | 一个合格真实数据集上的既有策略回测结果 → 参数调整和运行 → 两次结果比较       | P5 对应前置；复用现有引擎，保留点时、费用和会计约束                                          |
| 模拟组合       | 已有模拟账户的只读资金/持仓 → 受控模拟意图与成交 → 模拟对账与报告            | P6 对应前置；开放写入/成交前完成适用会计、幂等、风控和恢复门槛，正式阶段退出耐久门禁不能跳过 |
| 场内贵金属基金 | 一个已核验分类基金的基础资料与日线 → NAV/iNAV 参考 → 点时折溢价展示          | P1-N13/N14、P5-N14、P6-N13 及各自前置；净值不作为可执行价格，不扩展现货/期货                 |
| QMT 模拟       | 按 Phase 7 节点拆分模拟账户查询、受控订单状态、重连对账等独立模拟切片        | Phase 6 退出与独立准入前置；有真实下单能力的路径仍禁止进入早期版本                           |

分钟/实时行情、邮件/短信、多用户/OAuth、公共 SaaS 和真实买卖继续保留在需求池，不自动混入上述小版本。真实买卖必须取得精确到节点和环境的独立授权并通过正式门禁，不能为一周节奏省略。

## 一周以内的执行规则

1. **开工锁定一个可用结果**：写清任务、文件范围、前置、非目标和直接验收；只细化当前及紧随其后的版本，不同时维护多套周计划。
2. **研究也计入工期**：2–5 日为目标、7 个自然日为上限，包含必要调研、开发、检查和发布收尾；不能把长期前置准备移出计时来宣称达标。
3. **第 2 日处理超期风险**：预计超过上限就拆小；外部来源或权限阻断时将该项后移，选择已就绪的独立切片。不得绕过必要依赖、用 fixture 冒充真实能力或削弱安全验收。
4. **完成即可收口**：只执行受影响检查和一次核心路径验收，复用有效结果，一份简短回执即可；不为等固定发布日期增加功能。确实无法安全交付时如实说明阻断，不发布假可用版本。

具体 Git/tag/部署/正式发布仍按已有授权边界执行；排期和版本规划本身不代表这些操作已经发生。当前源码包版本、候选 SHA 和实际发布结果以[首发清单](2026-10-12-v1.0-release-plan.md)和真实回执为准。
