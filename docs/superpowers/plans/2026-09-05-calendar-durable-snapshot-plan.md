# 日历稀疏来源快照持久化计划

## 范围与风险

节点 P1-N07，补齐已确认的内存仓储无法跨进程恢复版本、修正和审计的缺口。
这是高风险数据完整性改动：采用 PostgreSQL 事务、追加式版本和迁移账本，必须经过
真实隔离数据库测试与独立审计。它不是完整交易日历、来源裁决或 PIT 交付。

不改行情公开契约、采集运行入口、既有 P6 改动、真实数据库或券商能力。
本切片只交付代码和隔离证据；实际迁移及本地原位更新另行预检。

## 实施顺序

1. 为持久化接口、事务所有权和迁移资源增加失败先行测试。
2. 沿用现有 worker migration 入口和共享锁，登记 V3 独立 SQL resource；未登记的
   部分表或账本/结构漂移失败关闭，不重写 V1/V2。
3. 增加版本、按顺序保存的闭市记录、scope 最新指针、精确修正和审计五类表。
   只有最新指针可更新，历史表禁止更新和删除；版本使用不透明 UUID。
4. 实现 PostgreSQL adapter，保存前校验与深拷贝。同来源、交易所、年份使用事务锁。
   可选稳定 `operation_id` 只存摘要；相同重试返回原版本且不倒退最新指针，冲突拒绝。
   未提供操作标识时每次新建版本，不按内容偷偷去重。
5. 使用真实 PostgreSQL 隔离 fixture 验证迁移、重启、并发、重试、失败回滚、精确修正、
   scope 隔离及历史不可变；执行受影响检查和 wheel 资源验证。
6. 独立审计后形成证据记录；不得将跳过集成测试计为通过。

## 事务和时间契约

adapter 借用连接但不拥有其生命周期；调用方不得同时在外部使用该连接。
每个公开方法仅接受 IDLE 连接，在内部互斥区创建自己的事务；调用方已有事务时固定
错误拒绝，不提交或回滚调用方工作。读取不留下隐式事务，写入成功后新连接可见。
方法内部通过 cursor helpers 复用查询，不能嵌套调用公开方法而产生保存点假提交。

`persisted_at` 仅表示仓储写入时间，不是来源 `available_time`，不提供历史 as-of。
隐式 correction 仅在该事务可见历史恰好一个版本时兼容；显式 correction 始终绑定
不变版本，且与该 scope 保存采用同一事务锁。不会据此推断完整交易日或证券生命周期。

## 验证边界

常规测试不调用真实行情源、账户或券商。未配置测试 DSN 时，可使用已缓存且与本地
版本相同的 PostgreSQL 一次性 fixture：唯一名称、临时数据、随机回环端口、临时密码，
不挂真实卷、不连接应用库、不启动第二套应用，结束时精确清理。凭据不写入证据或日志。

验收要求涵盖成功路径、边界、故障恢复及并发；格式、静态检查和测试仅扩展至直接
受影响的日历、迁移及相关调用者。Windows/macOS/Linux 使用标准 Python 路径与资源 API；
本机和 Linux 容器的成功不能替代未执行的平台测试。
