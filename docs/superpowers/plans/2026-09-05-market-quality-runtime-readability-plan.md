# 行情质量公开产物跨用户读取修复

## 范围

P1-N12，风险高。用户要求继续补齐已发现缺口，并在完成后更新现有本地环境。
本切片先修复已经发现的公开产物权限缺陷，不能据此宣称完整日历、PIT、全市场覆盖
或正式墙钟门禁完成。原有 P6 和日历工作区修改保持不变。

## 当前证据

`quality_export._atomic_write()` 用 `NamedTemporaryFile` 创建公开文件后直接替换目标。
本机隔离探测结果为 `public_artifact_mode=0o600`。Dockerfile 中 worker 使用 UID 10001，
server 使用 `node` 用户；仅挂载只读卷不足以使不同 UID 的 API 读取文件。

该问题仅涉及已白名单脱敏的 `current.json` 与公开快照。不得更改原始质量文件、
manifest、raw object 或现有目录的权限，也不得通过更换 API 用户、添加组、特权模式
或挂载原始卷解决。

## 执行与验证顺序

1. 先添加 POSIX 产物权限回归，并确认现有导出得到仅 owner 可读的文件。
2. 独立审核新产物 owner 可写、其他用户只读的最小方案；只调整新临时文件，提交前
   完成权限设置和同步。权限设置失败时不得发布新指针。
3. 检查目录可遍历前提，不能在后台递归放宽现有目录。
4. 验证完整导出、再次发布、失败保留旧指针，以及原始文件内容与模式保持不变。
5. 运行受影响导出测试、静态检查和独立审核；POSIX 权限语义与 Windows 平台限制
   分别说明，不将跳过视为 Windows ACL 验证。
6. 再决定精确的 Compose overlay、卷初始化和运行验收；本计划本身不启动服务、
   导出真实数据或创建公开卷。

## 后续依赖

公开卷实际启用仍需唯一 writer、API 只读挂载、可信目录与认证接口验收。
日历持久化、来源证据时间、完整交易日及行情缺口判定属于独立依赖链，不能从当前
稀疏闭市记录或 `OBSERVED_ONLY` 入库明细推导。正式墙钟验收仍按既有条件接受记录处理。
