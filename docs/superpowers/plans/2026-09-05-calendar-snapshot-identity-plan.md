# 日历快照复合身份与修正隔离

## 范围和前提

节点为 P1-N07，基线 `d1847c0`。上一项已校验单次请求与返回记录的交易所和年份；
本轮修复同一来源的不同合法请求仍共享最新指针，以及未绑定版本修正跨范围出现的问题。
风险为高：涉及来源版本、读取歧义与修正审计。先由 Terra Max 核对调用方与兼容性，
实施后独立审核；保持原有 P6 修改及历史证据不变。

只改内存 calendar repository、collector 接线、相关测试与文档。不实现 PostgreSQL、
迁移、PIT、完整交易日历、任务恢复或新公共 HTTP/JSON 契约。不提交本轮新代码或部署。

## 设计决定

1. 以 `(source, exchange, year)` 作为内部不可变身份，最新指针按此身份分别保存。
   每个版本记录自身 scope，包括零条闭市记录的版本。
2. 保留 opaque `source:year:vN` 版本 ID 格式，不解析 ID 获取 scope。
3. `save_version(source, year, holidays, *, exchange=None)` 保留旧三位置参数。
   collector 总是显式传交易所；旧非空同质列表可推断，旧空列表不猜归属。
   仓储再次验证完整范围并深复制，全部成功后才分配版本、更新索引和审计。
4. `source_holidays(source, *, exchange=None, year=None)` 接受完整显式范围。
   source-only 在没有记录或仅一个 distinct scope 时兼容；多 scope 或部分参数时
   拒绝，不能静默挑选最后写入者。新增 `latest_version_id` 区分空快照与从未采集。
5. 修正必须绑定准确版本。省略版本仅在仓储恰有一个历史版本时推定；零或多版本拒绝，
   即使它们同属一个 scope 也不能猜最新版本。修正日期必须为目标年份内的标准 ISO 日期。
6. 修正读取只返回指定版本的修正。省略版本的零版本读取返回空，单版本兼容，多版本
   拒绝。不得再把未绑定修正作为适用于所有版本的规则。

这些兼容收紧仅针对原本没有唯一答案或不合法的内部调用；已有有效单范围/单版本调用、
深复制、历史版本读取、修正不覆盖来源数据及 `UNKNOWN` 覆盖语义均保留。

## 验证

先以新回归测试复现缺口，再最小实现。覆盖同源跨所跨年、不同来源、空快照、定向重采、
历史不变、旧调用兼容、歧义拒绝、错误无回显和失败前后索引/计数/审计不变。
修正覆盖显式目标隔离、多版本隐式调用拒绝、跨年和非法日期拒绝。

运行变更文件的 Ruff 格式/lint、Basedpyright，日历 collector/repository 与直接关联的
market-core 日历测试，以及一次 data-worker 离线包测试。仅清除测试 DSN，让需要真实
PostgreSQL 的 fixture 按既有规则跳过，不访问真实数据库、行情源或凭据。

完成后记录实际命令与结果，独立审查接口、数据一致性和剩余限制。内存身份隔离通过
不等于持久化或时点查询通过，不改变最终墙钟资格。
