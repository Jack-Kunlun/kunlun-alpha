# 计划 05：P1-N12 来源价格差异对账

## 目标

对同一证券、交易日、周期和价格类型的可比较行情版本做来源差异检测，保留原始证据并产生
可解释告警；不在本计划中选择交易价格 winner。

## 范围与非目标

- 比较 RAW 日线的 OHLC、成交量和成交额；复权数据必须按相同算法/版本另行比较。
- 使用 `Decimal` 或整数比例，不使用无约束浮点。
- 阈值按字段、市场和版本显式配置，带生效时间和审计。
- 官方日历只限定可比较日；第三方来源不能覆盖官方日历结论。
- 不修改原始 bar，不静默丢弃差异，不把 NAV/iNAV 当作可成交价格。

## TDD 与实施顺序

1. 先定义并测试对齐键、Decimal 比较、零基数、停牌零成交、缺一来源、修订版本、迟到数据、
   复权混用、币种/单位冲突和未来数据泄漏。
2. 定义版本化 difference assessment/alert 契约及证据引用。
3. 实现纯比较器和 ClickHouse 点时 reader；输入不完整返回 `INDETERMINATE`。
4. 持久化不可变评估和阈值版本；同一 operation 幂等，不覆盖旧算法结果。
5. 增加 API/UI 的字段级差异、绝对值/比例、来源时间、版本和原始脱敏证据链接。
6. 使用冻结、契约兼容的重叠 fixture 和既有自然数据完成实现验收；真实 AKShare/Tushare
   重叠样本的最终对账放入计划 06，避免与真实采集形成依赖环。

## 验收标准

- 同一对齐键在不同输入顺序下输出完全一致。
- 阈值内、阈值外、缺源、冲突版本和不可比较单位均有明确状态和理由。
- 新阈值/算法生成新版本，历史告警可重放；不得为使测试通过更新无解释基线。
- 页面可按日期、证券、来源对、字段和状态定位差异，空态不表示“来源一致”。
- 查询与告警无秘密、路径、raw body 或高基数 metrics label 泄漏。

## 验证范围

- 纯域 Decimal/PIT/顺序稳定性测试。
- ClickHouse reader、PostgreSQL audit/alert、contracts、server/web 定向验证。
- 冻结重叠 fixture 和既有自然数据只读验证；真实重叠样本 E2E 由计划 06 完成。不写正式行情
  表，不启动 P6 门禁。
