# P0–P6 未完成项闭环总计划

日期：2026-09-09

## 1. 目的与判定口径

本目录把权威 98 节点手册中 P0–P6 的当前状态与后续执行计划分开记录。状态判断同时要求有
源码、验证和运行证据；仅有文件、提交标题、空结果、HTTP 200 或数据库对象存在，均不能单独
证明节点已经完成。

状态枚举：

- `CLOSED`：节点交付和验收已有直接证据，当前未发现需要重新打开的阻断。
- `PARTIAL`：基础能力存在，但新增或原验收要求尚未完整闭环。
- `IMPLEMENTED_UNACCEPTED`：工作区已有实现，仍缺真实依赖、数据库、镜像或端到端验收。
- `FORMAL_GATE_OPEN`：功能证据可继续使用，但正式退出门禁未通过。
- `BLOCKED_EXTERNAL`：缺少凭据、官方来源授权或其他外部条件，必须失败关闭。
- `BLOCKED_DECISION`：缺少用户拥有的身份、权限、来源或架构决定，不得自行选择或绕过。

## 3. 当前事实基线

- 当前分支为 `master`，工作区存在大量已跟踪和未跟踪修改；全部先按用户工作处理。
- P1-N12 已能查询日线 `OBSERVED_ONLY` 概览/日期和 14 条脱敏 `FILTERED` 证据，但不能据此
  判断缺失交易日或全市场完整性。
- P1-N07 已保存 SSE 2026 年 19 条稀疏休市公告；SZSE V4 快照有 365 个自然日，但官方确认
  窗口只到 2026-09-07，窗口外为 `INDETERMINATE`。SSE 完整逐日来源、BSE 来源和临时休市
  仍未闭环。
- Calendar Quality V5 已具备不可变质量账本、封存角色和一次性发布入口；它不自动启用
  scheduler、API 或采集。
- P1-N06 工作区已有 Tushare 证券主数据、生命周期、私有 PostgreSQL 和一次性运行入口；
  离线定向测试可通过，但真实 PostgreSQL、正式角色/迁移、真实 Tushare 和镜像运行证据仍需
  在独立验收中完成。
- 行情源配置已具备管理员配置、加密存储和 worker 安全读取边界；尚无“保存配置 → 实际拉取 →
  raw/质量证据 → ClickHouse → API/UI”的真实 AKShare/Tushare 端到端证据。
- P1-N14 的贵金属基金契约、采集和校验代码存在，但未取得真实 provider、实际 PostgreSQL
  和运行监控证据。
- P3-N07/N08/N09/N10 缺生产模型/存储适配、热点物化、可信反馈授权或真实上游写入；P4-N03/
  N07/N08/N09/N10 缺真实采集、持久媒体处理、可信审核、特征物化或持久工作台投影。其余
  P3/P4 节点只做回归前置，不先重写。
- P6-N13 页面/API/测试存在，但尚未以通过 P1 完整性门禁的真实输入完成来源、时效、版本和
  降级状态验收。
- 现有 Docker 项目基础服务、server 和 web 正常运行；当前没有持续的 calendar、instrument-master
  或 market-data-sync 任务。
- P6-N12 R4 仅为条件接受；独立结论仍是 `INVALID / CLOCK_ELAPSED_MISMATCH`。正式 24 小时
  连续墙钟门禁必须等待候选版冻结后从零执行。

## 6. 全局停止条件

- 官方来源身份、覆盖终态或可见时间不足时返回 `INDETERMINATE`，不得合成肯定结论。
- 缺少真实 provider 凭据时记录 `BLOCKED_EXTERNAL`，不得使用假成功代替真实 E2E。
- P3/P4 的可信 HTTP 身份来源、角色/权限、服务间信任和审计 actor 未获用户批准前记录
  `BLOCKED_DECISION`，保持 `DenyAll`，不得使用客户端 Header 或 `AllowAll` 绕过。
- 不在现有工作区上覆盖、清理或回退无关修改；提交、推送仍需明确授权。
- 所有真实外网验收均为人工受控步骤；自动测试继续使用 fake/fixture，不访问真实账户。
- 仅更新现有 Docker 项目，不创建第二套部署，不删除现有卷，不把测试数据写入正式库。
- P0–P6 保持 `PAPER_ONLY`，不得引入券商 SDK、真实账户凭据或可调用真实订单路径。

## 7. 最终完成定义

只有计划 0–13 均取得各自证据包、候选版被冻结、正式 24 小时门禁由独立只读检查器返回
`QUALIFIED`，才可声明当前 P0–P6 缺口全部关闭。任何计划未完成时，P6-N12 和 Phase 6 都
保持未正式关闭。
