# 计划 10：P6-N13 贵金属专题终端真实输入验收

## 目标

在 P1-N14 和 P5-N14 的合格输入上，验证贵金属基金专题终端的行情、metadata、NAV/iNAV、
溢折价、流动性、事件、排行和预警链路，不把 fixture 页面当成真实数据验收。

## 已有基础与缺口

- P6-N13 API、页面和自动测试已经实现。
- P5-N14 的点时特征和非可成交参考价边界已有实现证据。
- 当前缺少真实 provider 数据下的来源、时效、版本、缺失/过期降级和端到端页面证据。

## 前置依赖

- 计划 01 的完整官方交易日历已通过。
- 计划 04–06 的 expected-bar、来源差异和真实 AKShare/Tushare 链路已通过。
- 计划 07 的贵金属 metadata/NAV/iNAV 真实运行已通过。

## 执行步骤

1. 在冻结候选前复验 P6-N13 合同、API、Web、可访问性和路由权限测试。
2. 正常场景使用计划 07 产生的受控真实数据；部分缺失、过期、来源冲突、未知分类和 provider
   不可用场景只使用隔离测试环境的显式 fault injection 或自然产生的既有证据，不人为中断真实
   provider，也不向正式表写假数据。
3. 验证 API 聚合遵守同一 `asOf`、来源/版本/币种和 `available_time`，不使用未来 NAV 修订。
4. 已认证浏览器验收列表、对比、详情、事件时间轴、自选/预警、loading/empty/error/forbidden。
5. 检查暗色、键盘、焦点、响应式和 stale/partial 文案；截图只含脱敏非秘密数据。

## 验收标准

- 每个指标显示数据时间、来源、版本和缺失原因；适用的模型/聚合指标显示样本量与置信度。
- NAV/iNAV 明确为参考值，不能显示为可成交价格；不出现现货、期货或真实下单入口。
- 输入过期、冲突或不可用时降级为 `PARTIAL/STALE/INDETERMINATE`，不复用旧值冒充当前。
- P1/P5/P6 的同一标的与 as-of 可追溯；报警重放幂等且不泄漏 provider token。
- 独立审查无阻断后，P6-N13 才从 `IMPLEMENTED_UNACCEPTED` 转为关闭。
