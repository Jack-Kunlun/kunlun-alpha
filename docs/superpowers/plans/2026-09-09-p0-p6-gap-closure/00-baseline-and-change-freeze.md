# 计划 00：基线与变更冻结

## 目标

在继续开发前，把当前大工作区按来源、节点和证据状态分组，建立不会覆盖用户修改的可复验
基线。该计划不增加产品能力，也不启动采集、迁移或门禁。

## 当前状态

- 当前分支为 `master`。
- 工作区同时包含日历 V3/V4/V5、证券主数据、行情证据、P6 耐久修复和文档修改。
- 部分能力已经进入本地镜像或正式数据库，部分只有源码和测试，不能按一个批次统一宣称完成。

## 执行步骤

1. 记录 `HEAD`、分支、tracked/untracked 清单和现有容器镜像/启动时间，只保存非秘密元数据。
2. 按 P1-N06、P1-N07、P1-N12、P6-N12、文档/运行证据建立文件归属表；冲突归属先停下复核。
3. 对每组记录源码 SHA-256、已运行检查、数据库/镜像/运行证据和未验收边界。
4. 只对当前计划直接覆盖的文件执行 diff 审核与窄验证；不得用全仓格式化制造无关改动。
5. 生成候选提交清单。只有取得明确提交授权后，才按节点和可回滚边界创建 Conventional Commit。

## 验收

- 每个改动文件只有一个明确 owner/节点；没有“来源不明但先提交”的文件。
- 代码、数据库迁移、运行启用、真实外网验收和正式门禁五类证据分别列示。
- `git diff --check` 通过；计划文件链接有效。
- 没有修改分支、提交、推送、删除文件、删除卷或重启服务。

## 停止条件

发现用户改动与待提交实现重叠、现有数据库状态与证据不一致、或文件无法归属时停止，先请求
用户决定；不得通过 reset/checkout/clean 解决。
