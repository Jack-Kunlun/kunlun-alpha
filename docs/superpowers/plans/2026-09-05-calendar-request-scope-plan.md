# 交易日历采集范围一致性修复

## 范围与风险

节点为 P1-N07 的采集输入与响应范围校验，前序代码基线为 `b80153a`。
手册要求同步交易所日历、保留版本来源及手工修正审计；本轮只补齐采集边界，不声称完成
日历持久化、完整覆盖判定或整个节点。

当前 `Holiday` 契约只允许 `SH`、`SZ`、`BJ`，记录包含闭市日期，但 collector 未验证
其交易所与日期年份是否符合本次请求。分页成功不能证明所有页属于请求范围。

涉及来源数据正确性，按高风险执行短范围研究、失败先行、实现后独立审核；不修改
仓储结构、公共 JSON Schema、权限、依赖、部署或既有 P6 文件。

## 验收条件

1. 请求交易所与年份必须合法；复用生成的 `calendar_holiday.Exchange` 枚举，交易所只接受
   `SH`、`SZ`、`BJ`，不纠正大小写或 vendor 别名。年份为严格整数 `1..9999`，拒绝布尔值。
   无效请求在调用 provider 或保存前受控失败。
2. 逐页校验每条 Holiday，交易所或日期年份不匹配时拒绝整个采集结果，不静默过滤、
   改写交易所或截断日期。
3. 首页和后续页的范围错误均不得保存部分版本，不得改变旧版本、最新来源记录及修正审计。
4. 错误使用既有错误分类与固定消息，不回显来源记录、自由文本 note 或请求中的任意输入。
5. 三个受支持交易所、合法跨页结果、年初年末及闰日保持可采集，成功仍只保存一次。
6. 保留已有分页上限、环路保护、未知覆盖状态及显式告警行为，不新增重试或恢复承诺。

## 实施与验证

先确认类型、调用方及公共语义，再由执行代理添加回归测试并观察预期失败，随后最小修改
collector。运行变更文件格式、lint、类型检查、日历采集与直接关联的日历领域测试，
并在不提供外部凭据或启动服务的前提下执行 data-worker 包的离线测试。
失败或审查发现更广影响时再扩大验证，不运行无关服务或真实网络任务。

不在当前请求下自动提交、部署、访问真实数据或启动任何门禁。完成后记录新鲜命令及
独立审核结果，再交由用户决定后续操作。

仓储当前只用 `source` 定位最新版本；即使本轮的每次响应合法，不同交易所或年份的
合法请求仍没有独立 latest 指针。该持久化身份缺口与 PIT 设计明确不包含在此次修复中。
