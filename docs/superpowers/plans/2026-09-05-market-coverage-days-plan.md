# 逐日入库明细实施计划

## 范围与依据

本次为 P1-N12 的独立观测切片，基线为 `e2254ce`。节点要求能够按日期、来源、证券
定位问题，当前日线入库概览只有首末日期和去重日数，不能查看具体日期。

本次只补足实际入库日期明细，不实现完整性判定。经只读检查，交易日历缺少持久化的
PIT 快照，证券生命周期与采集任务终态也尚未形成可供缺失判定使用的完整链路。
这些前置条件未满足前，不得将无 Bar 解释为缺失、采集失败、停牌或休市。

## 接口与语义

- 新增只读 `GET /api/v1/data-quality/market-coverage/days`。
- `unifiedCode` 和单个支持的 `source` 必填，日期规则沿用入库概览：单日或闭区间，
  默认 90 个自然日，最多 366 个自然日。
- 响应版本为 `market-data-coverage-days-v1`，范围为
  `DAILY_RAW_SINGLE_SUPPORTED_SOURCE`，含义固定为 `OBSERVED_ONLY`。
- 返回窗口、服务端固定的 `asOf`、证券、来源，以及按日期升序去重的 `days`。
  每日含日期及独立聚合的最新 event/available/processing 时间，不返回价格。
- 查询严格限定 RAW/DAILY、单证券、单来源与日期范围，三类时间均不晚于同一 `asOf`。
  不使用跨来源 winner，不过滤停牌 Bar，不生成不存在的日期。
- 明细是独立查询，不承诺与之前汇总处于同一数据快照；页面显示自己的查询时点。
- 未配置、异常结果和读取失败为受控不可用，不转换为成功空列表。

## 实施顺序

1. 先写并运行失败测试，固定契约、参数和只读查询语义。
2. 新增契约并生成共享类型，实现受控 API 与有界 ClickHouse 读模型。
3. 从概览行进入明细；保留加载、空、错误、无权限状态及有限页面行数。
4. 执行契约同步、相关模块测试，以及受影响服务/页面的格式、lint、类型和构建检查。
5. 审查最终差异、授权顺序、来源隔离、PIT 截止和空态文案，记录实际验证结果。

## 风险与非目标

风险为中等：新增公共只读接口及前后端契约，但不改变存储结构、凭据或授权模型。
不部署、不建库、不迁移、不采集或回填真实数据；实现验收后，项目负责人另行授权提交本切片。
既有 P6 修改与条件接受记录保持原样。之前的公开拒绝证据运行启用仍待独立安全审核。
缺失交易日判定、来源价格对账、全市场证券覆盖和真实交易均不属于本次交付。
