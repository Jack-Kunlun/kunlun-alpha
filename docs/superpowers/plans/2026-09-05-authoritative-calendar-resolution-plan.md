# 权威逐日日历判定切片

节点 P1-N07，风险高：影响时间可见性与数据完整性解释。用户已批准官方权威、次源
冲突留证、不足则无法判定。先实现纯域规则，验证通过并独立审计后再交付；不自动把
静态日历、稀疏 Holiday 或第三方来源提升为官方证据。

## 限定实现顺序

1. 在 market-core/calendar 中新增独立不可变逐日快照、scope、authority 和三态判定。
   不扩 shared JSON/HTTP 契约，不修改旧 TradingCalendar、数据库或页面观测口径。
2. 先通过失败测试固定全年 365/366 日、输入类型、不可变性和时点边界。
3. COMPLETE 必须逐日无缺漏、无重复；合法的未完成快照只能返回无法判定。
4. 以 available_at 判定可见性，只有显式、合法且同范围的 supersedes 关系允许替代。
   不按抓取时间或字典顺序解决同级官方冲突。新未完成尝试阻断旧完整快照回退。
5. 次源只能产生显式冲突证据，不能覆盖、补全或提高官方完整性；未来次源不可见。
6. 新旧日历定向测试、格式、lint、类型检查及独立数据完整性审核后形成证据包。

## 信任与交付边界

内部 closed authority enum 与交易所固定映射只校验契约，不证明外部真实性。未来官方
adapter 必须独立验证端点、文档身份及捕获证据，再在受信任组合入口传入该类型；不能
由任意 URL、source 字符串或自报 metadata 获得权威资格。仓库目前无已运行的完整官方
日历采集器，因此本切片不会使实际覆盖状态由 OBSERVED_ONLY 变成完整合格。

日历 scope 使用交易所和年份；证据 ID 不透明，错误与判定输出不带原始 note/URL。
数据库持久化、官方采集、证券生命周期和完整性 API 接线是后续独立切片，正式墙钟
门禁继续延期，不扩大实盘能力。
